# CS236 — Operating Systems Lab

My solutions for the OS lab (CS236, Spring 2025, IIT Bombay). The lab sequence
follows Mythili Vutukuru's OS course: a warm-up with Linux process/memory
tooling, a shell built from `fork`/`exec`/`wait`, three labs inside the
[xv6](https://github.com/mit-pdos/xv6-public) teaching kernel, one on POSIX IPC,
and one on pthreads synchronisation.

Each lab directory keeps its own problem-statement PDF next to the code. Course
handouts and lab-quiz papers are in [`docs/`](docs/).

## Lab 1 — Linux tools

Read machine configuration out of `/proc/cpuinfo` and `/proc/meminfo`, watch a
spinning process with `top`, trace the shell's process tree with `ps`, and see
where fd 0/1/2 point under redirection (`> file`) and pipes (`| grep`) to work
out how the shell implements both.

`memory1.c` / `memory2.c` allocate the same large array but only one touches it —
comparing VSZ against RSS shows physical pages arriving only on access.
`disk.c` / `disk1.c` read 5000 copies of a PDF (generated by `make-copies.sh`)
sequentially vs. with different access patterns, measured with `iostat` after
dropping the buffer cache.

```sh
cd lab1-intro_to_linux_tools
gcc cpu.c -o cpu && ./cpu          # then `top` in another terminal
mkdir -p disk-files && cp foo.pdf disk-files/ && ./make-copies.sh
```

## Labs 2–3 — Building a shell

`my_shell_A.c` → `my_shell_D.c` are the incremental builds, one file per part:

- **A** — tokenise input, `fork` + `execvp` + `wait`, reap children, `cd` via
  `chdir` in the shell process itself (not a child), graceful error handling.
- **B** — background execution with `&`; children reaped lazily with `waitpid`
  so a finishing background job never releases a foreground `wait`.
- **C** — `exit` builtin, which kills all outstanding background processes and
  frees shell state before terminating.
- **D** — a `SIGINT` handler that kills only the foreground child. Background
  children are moved to their own process group with `setpgid(0,0)` so Ctrl+C
  never reaches them.

`my_shell.c` is the consolidated Part-D shell. Warm-up exercises (`fork`/`wait`
ordering, `exec` variants, `runcmd`, signal handlers) are in
[`practice_exercises/`](lab2-shell-code/practice_exercises).

Part E (serial `&&` / parallel `&&&` foreground execution) was only ever
attempted in `shell_modified_bad.c`, which does not work — it is kept for
reference, not as a solution.

```sh
cd lab2-shell-code && gcc my_shell_D.c -o shell && ./shell
```

## Labs 4–5 — Processes in xv6

Worked solutions are in
[`xv6-proc-solution/`](lab4-xv6-proc/xv6-proc-solution), one directory per part,
each holding the full set of modified xv6 files (`proc.{c,h}`, `syscall.{c,h}`,
`sysproc.c`, `defs.h`, `user.h`, `usys.S`). Drop a part's files into a clean xv6
tree and `make` to build it.

- **A** — syscalls `hello()`, `helloYou(name)`, `getNumProc()`, `getMaxPid()`,
  and `getProcInfo(pid, &processInfo)` returning parent PID, context-switch
  count and process size. `struct proc` gains a field to count how often the
  scheduler switches a process in; `ptable` is read under its spinlock. Together
  these are enough to write a `ps` clone in userspace.
- **B** — a weighted round-robin scheduler driven by `setprio(n)`/`getprio()`.
  Priority acts as a weight so higher-priority processes get proportionally more
  CPU, while low-priority ones still make progress rather than starving. New
  processes inherit a sensible default priority.
- **C** — `welcomeFunction(fn)` / `welcomeDone()`: a forked child resumes first
  inside a parent-set welcome function and only afterwards returns to the code
  following `fork`. This works by rewriting EIP in the child's trap frame at
  fork time and restoring the saved value when the child calls `welcomeDone`.

The starter patch and the six test cases are in
[`xv6-proc-code/`](lab4-xv6-proc/xv6-proc-code). `warmup-notes.md` walks through
how a syscall is threaded through `usys.S`, `syscall.{c,h}`, `sysproc.c` and
`defs.h`.

## Lab 6 — Inter-process communication

- **A** — `shm-posix-producer.c` / `shm-posix-consumer.c` share a 4 KB POSIX
  shared-memory segment holding 512 eight-byte slots, initialised to `"freeeee"`.
  The producer writes strings and announces each slot's offset over a named pipe;
  the consumer prints the string, blanks the slot back to the free pattern, and
  sleeps. 1000 strings are exchanged over 512 slots, so the producer blocks and
  reuses slots once the consumer falls behind.
- **B** — `socket-client.c` / `socket-server.c` transfer a file over a Unix
  domain socket in 256-byte chunks; the server prints what it receives.
- **C** — `my_shell_D.c` here extends the Lab 2 shell with pipes
  (`cat foo.txt | grep hello`), forking one child per command and wiring
  stdin/stdout to the pipe with `dup2`, closing every unused descriptor.

Originals from the handout are in [`ipc-code/`](lab6-ipc/ipc-code).
`lab6-ipc-old/` is an earlier iteration, kept for history.

```sh
cd lab6-ipc
gcc shm-posix-producer.c -o prod -lrt && gcc shm-posix-consumer.c -o cons -lrt
gcc socket-server.c -o server && gcc socket-client.c -o client
```

## Lab 7 — Memory management in xv6

Solutions live in [`xv6-public-AB/`](lab7-xv6-mem/xv6-public-AB), a clone of
upstream xv6. The touched files are `syscall.{c,h}`, `sysproc.c`, `defs.h`,
`user.h`, `usys.S`, `proc.c`, `trap.c`, `vm.c` and the `Makefile`.

- **A** — `numvp()` counts user virtual pages up to the process size (including
  the stack guard page); `numpp()` walks the page table with `walkpgdir` and
  counts entries with a valid physical address.
- **B** — `mmap(nbytes)` grows the address space at the program break and
  returns the new region's base **without allocating any physical memory**.
  Backing pages are allocated in a new `T_PGFLT` handler in `trap.c`, one page
  per fault, with `switchuvm` called afterwards to refresh CR3 and the TLB.
  `numvp()`/`numpp()` from Part A make the demand-paging visible: virtual page
  count jumps at `mmap`, physical count only creeps up as pages are touched.

Test with `tc_numpp` and `test-mmap` from the xv6 shell.

**Part C (copy-on-write `fork`) was not implemented.**
`xv6-public-C/` was set up as the clean checkout for it but contains no CoW work
— no page reference counts in `kalloc.c`, no `getNumFreePages()` syscall.

## Lab 8 — pthreads and synchronisation

- **[`warmup/`](lab8-threads/warmup)** — thread creation, argument passing, and
  ordering N threads with condition variables (print `1..N`, then `1..N` on
  repeat) without busy waiting.
- **[`master-worker/`](lab8-threads/master-worker)** — a bounded-buffer thread
  pool: `P` masters produce `M` integers into an `N`-slot buffer, `C` workers
  consume them. Every integer is produced and consumed exactly once, producers
  block on a full buffer and consumers on an empty one, using only mutexes and
  condition variables. `test-master-worker.sh` + `check.awk` verify the
  invariant on the output.
- **[`rwlock/`](lab8-threads/rwlock)** — reader-writer locks in both flavours
  sharing one `rwlock.h`: `rwlock-reader-pref.cpp` lets new readers join while a
  writer waits, `rwlock-writer-pref.cpp` blocks them so writers are not starved.
- **[`zemaphore/`](lab8-threads/zemaphore)** — counting semaphores
  (`zem_init`/`zem_up`/`zem_down`) built from a mutex and a condition variable,
  then used in `test-toggle.c` to interleave three threads in strict
  `thread0, thread1, thread2, ...` order using semaphores only.

**Part D (an original synchronisation problem, solved twice — once with
condition variables, once with zemaphores) was not attempted.**

```sh
cd lab8-threads/master-worker && gcc master-worker.c -o master-worker -lpthread
cd ../rwlock && ./test-rwlock.sh
cd ../zemaphore && ./test-zem.sh
```

## Lab 9 — Threads and synchronisation in xv6

Solutions live in
[`xv6-public-unmodified/`](lab9-xv6-threads/xv6-public-unmodified) — the name is
a leftover from the clone; it does contain the solution. Modified files:
`proc.{c,h}`, `syscall.{c,h}`, `sysproc.c`, `defs.h`, `user.h`, `ulib.c`,
`usys.S`, `vm.c`, `Makefile`. Course-provided patch files are in
[`xv6-public-patch/`](lab9-xv6-threads/xv6-public-patch).

- **A** — `waitpid(pid)` reaps one named child and returns its PID, or `-1` if
  it is not a child; a later `wait()` must not return the same child again.
- **B** — a kernel barrier: `barrier_init(N)` and `barrier_check()`, where the
  first `N-1` callers block and the `N`-th releases everyone, built on xv6's
  `sleep`/`wakeup` and spinlocks (`barrier.c`).
- **C** — real threads: `thread_create(tid*, fn, arg)`, `thread_exit()`,
  `thread_join(tid)`. Threads share the parent's page table but each gets a
  fresh writable user stack page, with the argument pushed onto that stack and
  EIP in the trap frame pointed at the entry function. `struct proc` tracks a
  `mainthread` pointer, and `fork`/`exit`/`wait` were adjusted so that `wait`
  blocks on the main thread and reaps every spawned thread with it.
- **D** — userspace spinlocks (`initiateLock`/`acquireLock`/`releaseLock`) in
  `ulib.c`, built purely on the atomic `xchg` instruction — no new syscalls.
- **E** — userspace condition variables. New syscalls `getChannel()`,
  `sleepChan()`, `sigChan()`, `sigOneChan()` expose sleep/wakeup channels to user
  code; `initiateCondVar`/`condWait`/`signal`/`broadcast` in `ulib.c` build the
  CV on top, releasing the lock before sleeping and reacquiring on wake.

Test programs `t_waitpid`, `t_barrier`, `t_threads`, `t_lock`, `t_l_cv1`,
`t_l_cv2`, `t_sem1`, `t_sem2`, `t_sleepwake` run from the xv6 shell.

## Building and running xv6

Any of the xv6 directories build the same way. You need the 32-bit x86
toolchain and QEMU:

```sh
sudo apt install qemu-system-x86 gcc-multilib
```

Then:

```sh
cd lab9-xv6-threads/xv6-public-unmodified
make
make qemu-nox          # Ctrl+A then X to quit
```

If the build complains about the host compiler being 64-bit, the usual fix is
already applied in these trees (`-m32` in `CFLAGS`, `TOOLPREFIX` left empty).
New user programs must be added to `UPROGS` in the `Makefile` to be compiled
into the filesystem image.
